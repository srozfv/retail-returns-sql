# Возвраты интернет-магазина за 30 дней

[![GitHub Actions](https://github.com/srozfv/retail-returns-sql/actions/workflows/check.yml/badge.svg)](https://github.com/srozfv/retail-returns-sql/actions/workflows/check.yml)

Портфолио · PostgreSQL · синтетические данные

Руководителю операций нужно выбрать связку «категория × канал» для детального разбора возвратов. Доля показывает частоту, а стоимость возвращённых позиций помогает оценить масштаб. [NRF рассматривает возвраты как отдельную операционную задачу розницы](https://nrf.com/media-center/press-releases/consumers-expected-to-return-nearly-850-billion-in-merchandise-in-2025). Данные этого исследования в проекте не используются.

## Результат

В срезе на 31.12.2025 полный 30-дневный период наблюдения есть у **8 261** из 9 000 доставленных позиций. В 30-дневное окно попали **804 возврата (9,73%)**.

| Сегмент | Доставлено | Возвращено | Доля | Стоимость позиций |
|---|---:|---:|---:|---:|
| Одежда · маркетплейс | 1 619 | 300 | 18,53% | 774 704 ₽ |
| Электроника · маркетплейс | 1 707 | 135 | 7,91% | 599 027 ₽ |
| Одежда · прямой канал | 1 085 | 136 | 12,53% | 348 324 ₽ |

В демонстрационном сценарии первым стоит проверить карточки одежды на маркетплейсе. У 182 из 300 возвратов в этом сегменте указана причина `Fit` (посадка или размер). На реальных данных следующим шагом был бы разбор по SKU и размеру с проверкой качества кодов причины. Генератор намеренно повышает вероятность возврата в этом сегменте, поэтому наблюдение описывает сценарий симуляции.

Декабрьская когорта включает только 1 декабря (19 позиций). Для помесячного сравнения используйте январь–ноябрь. Все строки и результаты доступны в [выводе PostgreSQL](results/postgres.txt).

## Определения

- Единица наблюдения — доставленная позиция, одна единица SKU. Полный возврат позиции возможен один раз.
- В знаменатель входят позиции с `delivered_on + 30 <= 2025-12-31`. Возврат на 30-й день включён. Возвраты после окна остаются в исходных данных.
- Месяц относится к дате доставки. Доля — число вернувшихся в окне позиций / число доставленных позиций с полным окном.
- Денежный показатель — сумма стоимости вернувшихся позиций, без учёта логистики, комиссии, состояния товара и себестоимости.
- Рейтинг учитывает только сегменты от 100 доставленных позиций. При равных суммах позиции делят место.

## Данные

`data/products.csv` — справочник из 12 SKU с категорией. `data/order_lines.csv` — ключ позиции `line_id`, ссылка `sku`, канал `channel`, дата доставки `delivered_on`, целая стоимость `amount_rub`, дата возврата `returned_on` и причина `reason`. Пустые дата и причина означают, что в срезе возврата нет. Обе таблицы созданы генератором, который задаёт распределения цен, дат и вероятностей. Источник состоит из вымышленных транзакций.

## Запуск

Из корня репозитория, с Docker и Compose. CSV уже включены. Для их пересоздания нужен Python 3.10+.

~~~sh
python generate.py      # опционально
docker compose up -d --wait
docker compose exec -T db psql -X -U analyst -d portfolio -f sql/run.sql
docker compose down
~~~

`sql/run.sql` пересоздаёт демонстрационные таблицы и представления в отдельной схеме `returns_demo` в одной транзакции. Ограничения PostgreSQL проверяют ключи, даты, значения каналов и согласованность даты и причины. Скрипт прерывается при первой ошибке. Запускайте его в локальной демонстрационной БД.

- `mature_lines` связывает позиции со справочником и определяет окно наблюдения.
- `monthly_cohorts` показывает помесячную долю и стоимость возвратов.
- `segment_priority` ранжирует сегменты оконной функцией `DENSE_RANK`.
- `sql/tests.sql` автоматически проверяет границы окна на четырёх контрольных строках, затем удаляет эти строки откатом к точке сохранения. После этого проверяются сверка когорт и знаменатели сегментов.

Синтаксис импорта — [документация psql](https://www.postgresql.org/docs/16/app-psql.html).
